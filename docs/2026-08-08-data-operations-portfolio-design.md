## 一、作品集定位与目标

**一句话定位**:一份以「数据运营」身份提交的求职作品集,证明「我能把数据变成可落地的运营决策」,而非「我会跑数据分析」。

**核心差异化**(区别于大众 Kaggle 项目):
> 大众分析:数据 → 图表 → "我们发现……"
> 我的作品:数据 → 图表 → "据此我要做……,因为数据说……"

**面向**:通用。任何游戏公司 / 电商 / 互联网运营岗都能投。作品集不绑定任何单一公司。

**成功标准**:
1. 面试官点开链接,能看出"这是数据运营做的,不是数据分析师做的"
2. 每个作品最后都有"可执行的运营方案",且每条结论都标注数据支撑
3. 两个作品形成"方法论 + 落地"的互补闭环

## 二、整体结构

```
作品集主页(个人介绍 + 2 个作品入口 + 简历下载)
├── 作品一:游戏向 · CS:GO 玩家对局行为与段位分层分析(主作品)
└── 作品二:通用向 · 电商用户生命周期与付费分析(方法论框架)
```

**互补逻辑**:作品二(电商)先建立"用户分层 → 生命周期 → 留存/付费"的**通用方法论框架**;作品一(CS:GO)把同一套框架**落到游戏场景**。面试时讲:"我有一套通用的用户分析框架,能迁移到任何产品——作品二展示框架本身,作品一展示框架在游戏里的落地。"

## 三、作品一:游戏向 · CS:GO(主作品)

**数据源**:Kaggle `skihikingkevin/csgo-matchmaking-damage`
- `mm_master_demos.csv`:玩家对局记录(伤害/击杀事件、胜者、玩家段位)
- 备用:`ektarr/counter-strike-pro-matches`(职业赛,补充高表现玩家画像)

**主题**:玩家行为画像 + 段位分层 + 运营落地方案

**分析框架**:
1. **数据清洗与探索**:处理缺失值、异常值(如击杀 0 的对局)、统一段位字段
2. **玩家行为画像**:击杀/存活/伤害/助攻 → 定义"活跃强度"和"行为类型"
3. **玩家价值分层**(核心):按行为把玩家分成 **核心玩家 / 成长玩家 / 流失风险玩家** 三类
4. **段位与行为关系**:不同段位的玩家行为特征 → 找"什么行为与高段位强相关"
5. **运营落地方案**(重点):基于分析输出可执行运营动作——
   - 新手引导该引导什么行为(数据:该行为与上段位强相关)
   - 怎么识别高潜力玩家(数据:高价值玩家的行为特征)
   - 流失风险玩家的预警信号与召回策略
   - 每条建议标注"由哪条数据支撑"

**页面结构**(运营型报告叙事):
```
① 项目背景(作为数据运营想解决什么问题)
② 数据与方法(数据来源、清洗、框架)
③ 玩家行为画像(分层图表)
④ 段位与行为洞察(关键发现)
⑤ 运营落地方案(分析→动作,带数据支撑)
```

## 四、作品二:通用向 · 电商(方法论框架)

**数据源**:Olist 巴西电商公开数据集(Hugging Face 镜像,免登录直连下载)
- 订单 / 客户 / 支付 / 评价 / 品类 / 地区,共 9 个 CSV

**主题**:用户生命周期 + 付费分析 + 方法论输出

**分析框架**:
1. 数据清洗与探索
2. 用户生命周期:首购时间 → 复购 → 流失,划分 **新客 / 复购 / 沉默 / 流失** 用户
3. 付费分析:客单价、付费频次、品类偏好 → 定义**高价值用户**
4. **方法论输出**(核心):把"用户分层 → 生命周期 → 付费价值"提炼成**可复用框架**(这是给作品一用的方法论)

**页面结构**:同作品一的运营型报告叙事(①背景 ②数据方法 ③核心分析 ④洞察 ⑤方法论输出)

## 五、呈现形式

- **网页形式**,每个作品是"运营型报告",不是图表堆砌
- 部署到 **GitHub Pages**,链接可直接投简历
- 技术:HTML/CSS + 图表(Python matplotlib/seaborn 导出的静态图,或 Plotly 交互图)
- 不做花哨框架,做干净专业的"运营报告"质感
